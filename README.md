## Encryption and KMS

Encryption is the process that uses algorithms to convert data into a secure format called ciphertext. Only authorised users can decrypt and restore the data to its original, readable state.
Companies and developers  use encryption to secure user data, transactions, files and more.
Encryption keys are sequence of characters or random bits that works with an encryption algorithm to transform readable data, known as plaintext, into an unreadable format called ciphertext.

AWS KMS is a secure vault for your encryption keys. You use KMS to create, manage, and use encryption keys that protect the data in your AWS resources.. Key management systems are important because one does not have to worry about losing them or someone stealing them as well as providing logs of usage for developers to meet compliance requirements for data security. 

Encryption keys are broadly categorized as symmetric and asymmetric. I set up a symmetric key because we are setting up an encryption key for a DynamoDB database. This means that the same key will encrypt and decrypt the database. One thing worth mentioning is that symmetric keys are used for a faster access and for large datasets.

## Encrypting Data

My encryption key will safeguard data in DynamoDB, which is one of AWS's database services. It is used for a fast and flexible data storage which makes it a great choice for applications that need quick access to large volumes of data.

The different encryption options in DynamoDB include:
1. Encryption owned by DynamoDB (Amazon DynamoDB fully manages the key, so you have no access or visibility to the key. Great for basic encryption where you don't need any control).
2. Encryption owned by AWS (You can see the key and its usage, but management is done by AWS).
3. Encryption owned by oneself, aka CMK. You create and manage the key in KMS, giving you full control. This is the most secure option and the one we're using in this project.
I selected the last option for this project.

## Data Visibility

Rather than controlling who has access to the key, KMS manages user permissions by assinging the right ones to the right users do specific actions, like encrypt and decrypt.

Despite encrypting my DynamoDB table, I could still see the table's items because I, as the user, have the permissions to use the encryption key. DynamoDB uses transparent data encryption, which means when data is requested by an authorized user (like myself) or an authorized application, DynamoDB retrieves the encrypted data, decrypts it with the key, then shows you the decrypted format so you can use it instantly

## Denying Access

I configured a new IAM user to get an autogenerated password. The permission policies I granted this user are "AmazonDynamoDBFullAccess" but I have not attached the encryption key.

After accessing the DynamoDB table as the test user, I encountered an error that showed the test user account does not have the permission to see the items in the Dynamo DB table because we have not assigned it the decryption key. This confirmed that the test user cannot see what is inside the table and that the KMS is only assigned to IAM user account.

## EXTRA: Granting Access

To let my test user use the encryption key, I had to go back into my IAM admin account, go into KMS and add the test user to Key Users. My key's policy was updated to  have both the IAM admin and test user in the Key Users section.

Using the test user, I refrehed the table in DynamoDB in the Incognito tab. I observed that now the test user indeed has the access to view the content of that table which confirmed that the update in Key Users worked.

Encryption secures data instead of blocking access controls to resources or services. I could combine encryption with permission policies and security groups to make sure that even if there is a breach of groups and policies, the actual contents in the resources would still stay protected as the person would not be able to see the data without the decryption key.
